## 1. Executive Summary

This document verifies the dual-channel customer ticket delivery system for the SSFI Lucky Draw fundraising platform:
1. **Primary Automated Channel:** Gmail API (OAuth 2.0) sending HTML and plain-text ticket issuance confirmations immediately upon Admin payment verification.
2. **Secondary Manual / Assisted Channel:** WhatsApp Click-to-Chat (`wa.me`) links for zero-cost, instant customer communication by staff and sellers without third-party messaging API expenses.

Both channels adhere strictly to data privacy, audit logging, fail-closed environment isolation, and idempotency guarantees.

## 2. Gmail Automated Delivery Architecture

### 2.1 Provider Selection & Environment Safety Gates

The delivery engine (`src/lib/delivery/service.ts` and `src/lib/delivery/providers/gmail.ts`) implements environment-aware provider selection:

```
                          [verifyPaymentAndIssueTickets]
                                       │
                                       ▼
                         [selectDeliveryProvider()]
                                       │
            ┌──────────────────────────┼──────────────────────────┐
            ▼                          ▼                          ▼
      VERCEL_ENV=                VERCEL_ENV=                Development /
       production                  preview                      Local
            │                          │                          │
   [Gmail API Live]          [checkGmailPreviewGate]       [Console Log
   Requires Client ID,                 │                    Simulation]
     Secret & Token          ┌─────────┴─────────┐
                             ▼                   ▼
                      GMAIL_PREVIEW_       GMAIL_PREVIEW_
                      REAL_SEND_ENABLED    REAL_SEND_ENABLED
                          != 'true'            == 'true'
                             │                   │
                     [mock_preview_        [Allowlist Check]
                        dry_run]                 │
                                       ┌─────────┴─────────┐
                                       ▼                   ▼
                                 Recipient ==        Recipient !=
                               ALLOWED_RECIPIENT   ALLOWED_RECIPIENT
                                       │                   │
                                 [Live Gmail]        [BLOCKED FAIL-CLOSED]
                                 (Staff auth)      (Simulated / Dry-run)
```

1. **Production Mode (`VERCEL_ENV=production`):**
   - Automatically uses the live Gmail API provider (`gmail_api`).
   - Validates that `GMAIL_API_CLIENT_ID`, `GMAIL_API_CLIENT_SECRET`, and `GMAIL_API_REFRESH_TOKEN` are non-empty.
   - Dispatches to the customer's verified email address upon ticket issuance.

2. **Preview Mode (`VERCEL_ENV=preview`):**
   - By default, falls back to `mock_preview_dry_run` with clear status `"Simulated (Preview Test)"`.
   - When live testing is explicitly activated with `GMAIL_PREVIEW_REAL_SEND_ENABLED=true`:
     - Checks `GMAIL_PREVIEW_ALLOWED_RECIPIENT`.
     - Validates that the active session belongs to an authorized `ADMIN` or `SUPER_ADMIN`.
     - Strictly blocks any email dispatch to real customer emails fail-closed, ensuring preview test data never sends surprise emails to customers.

3. **Development Mode:**
   - Falls back safely to in-memory console simulation (`mock_console`).

### 2.2 Trigger Lifecycle & Idempotency

- **Issuance Hook:** When an admin reviews a payment and executes `verifyPayment(orderId, paymentId)` in `src/server/actions/operations.ts`:
  1. The payment is verified in the database transaction and tickets are minted.
  2. `dispatchOrderTicketDeliveries(orderId, "PAYMENT_VERIFIED")` is invoked.
  3. The system queries the customer's email and phone number, the minted ticket numbers, and campaign metadata.
  4. An audit record is created before dispatch.
  5. If an email has already been marked as `SENT` or `DELIVERED` for this order, re-dispatching is skipped to prevent duplicate delivery.

### 2.3 Email MIME Structure & Customer Content

The email payload generated by `src/lib/delivery/templates.ts` includes:
- **RFC 2822 Multi-part MIME:** Clean HTML body with responsive table layout + plaintext alternative body.
- **Header Metadata:**
  - `From: SSFI Lucky Draw <senthangstudents@gmail.com>`
  - `To: <customer_email>`
  - `Subject: SSFI Lucky Draw — Your Official Ticket Confirmation [Order #{orderNumber}]`
- **Customer Body Details:**
  - Official Organization Name: Senthang Students' Fellowship India (SSFI)
  - Customer Full Name
  - Order Number (e.g. `ORD-2026-XXXXXX`)
  - List of All Issued Ticket Numbers (e.g. `SSFI-000001, SSFI-000002`)
  - Total Tickets Count and Amount Paid (in INR)
  - Date & Time of Issuance (formatted in Indian Standard Time, IST)
  - Official Ticket Verification Link (`https://ssfiticket.vercel.app/verify/{ticketNumber}`)
  - Official Public Draw Date: `19 December 2026`
  - Support & Inquiries Contact: `Senthangstudents@gmail.com`
- **Zero Sensitive Data:** Neither UPI reference numbers, bank account numbers, OAuth tokens, nor internal server credentials appear anywhere in email bodies or subject lines.

### 2.4 Error Sanitization & Diagnostics

- All Google OAuth errors during token refresh are passed through `sanitizeOAuthError()`.
- Client secrets, refresh tokens, and `Authorization: Bearer ...` headers are redacted to `[REDACTED]` prior to logging.
- Admin UI diagnostic alerts present actionable human-readable troubleshooting guidance (e.g., "OAuth token expired; refresh token must be re-consented in Google Cloud Console") without exposing sensitive strings.

## 3. WhatsApp Click-to-Chat Free Integration

### 3.1 Zero-Cost Direct Delivery Model

Rather than incurring recurring costs or per-message fees via third-party WhatsApp Business BSP APIs (e.g. Twilio, Meta Cloud API), SSFI Lucky Draw uses direct, official WhatsApp Click-to-Chat (`https://wa.me/` protocol).

Staff members and sellers can trigger instant, pre-filled WhatsApp delivery directly from their web browser or mobile phone:
- Free of cost.
- Instant delivery directly from the organizer's or seller's phone.
- No third-party account approval or template pre-approval delays.

### 3.2 Phone Number Normalization

The normalization engine (`src/lib/delivery/whatsappUrl.ts`) processes phone numbers entered by customers:

| Input Example | Processed E.164 Clean Format | wa.me Target |
|:---|:---|:---|
| `8810366357` (10-digit Indian) | `918810366357` (India +91 defaulted) | `https://wa.me/918810366357` |
| `08810366357` (leading zero Indian) | `918810366357` | `https://wa.me/918810366357` |
| `+91 88103 66357` (spaced +91) | `918810366357` | `https://wa.me/918810366357` |
| `+1 415 555 2671` (US international) | `14155552671` | `https://wa.me/14155552671` |
| `+44 20 7946 0991` (UK international) | `442079460991` | `https://wa.me/442079460991` |
| `+95 9 123 456 789` (Myanmar) | `959123456789` | `https://wa.me/959123456789` |

### 3.3 Message Template & Privacy Verification

The generated WhatsApp message includes:
```text

Your official tickets have been issued:
Order: {Order Number}
Tickets ({Count}): {Ticket Numbers}

```

**Privacy Guarantee:** The WhatsApp message strictly excludes payment UTR numbers, customer email addresses, and admin identifiers.

### 3.4 Accurate Delivery Status Lifecycle

The system accurately distinguishes between simulated, prepared, opened, and confirmed deliveries:

| Status Code | Display Label | Semantic Meaning |
|:---|:---|:---|
| `PENDING` (Email) | `Email Queued` | Message is queued for automated background dispatch. |
| `PENDING` (WhatsApp) | `Prepared` | Ticket message text and wa.me link are ready for opening. |
| `WHATSAPP_LINK_OPENED` | `WhatsApp Link Opened` | Admin or seller clicked the "Open WhatsApp" button. |
| `MANUALLY_SENT` | `Manually Confirmed Sent` | Admin or seller verified that message was dispatched in WhatsApp. |
| `SENT` | `Provider/API Accepted` | Gmail API HTTP 200 OK received; message accepted for transmission. |
| `DELIVERED` | `Delivery Confirmed` | Recipient server confirmed receipt (or seller confirmed hand delivery). |
| `SIMULATED` | `Simulated (Preview Test)` | Run in Preview dry-run mode without sending live transmission. |
| `FAILED` | `Failed` | Delivery attempt encountered a network or API error (diagnostic logged). |

1. **Google Cloud Console OAuth Configuration:**

   - [ ] Scope: `https://www.googleapis.com/auth/gmail.send`

   - [ ] `GMAIL_API_CLIENT_SECRET` set in Production environment.
   - [ ] `GMAIL_API_REFRESH_TOKEN` set in Production environment.
   - [ ] `SUPPORT_EMAIL=Senthangstudents@gmail.com`

3. **Fallback & Manual Assistance:**
   - [ ] If Gmail API encounters unexpected rate limiting or quota exhaustion, Admin and Seller Order Details screens retain one-click WhatsApp Click-to-Chat links to immediately fulfill ticket delivery.
